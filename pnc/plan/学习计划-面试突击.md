### Day 3：路径规划模块（3h，重点模块）

**阅读材料**：
- `path_planner/docs/2-架构说明.md`（全文）
- `path_planner/docs/3-使用示例.md`（重点看 API 调用流程）
- `path_planner/docs/debug_docs/FRENET_采样路径生成原理详解.md`（选读核心段落）

**必须掌握的 3 个核心概念**：

**面试必问题 1："路径规划用什么方法？"**

> 回答模板："我们用的是**基于 Frenet 坐标系的采样路径规划**。核心思路是：把参考路径投影到 Frenet 坐标系（s-d 坐标），在横向偏移 d 方向做采样生成候选路径，然后通过多目标成本函数（路径长度、平滑度、安全性、横向偏移）评估每个候选路径，最后选最优的。这样做的好处是——采样空间从 2D 降到了 1D，计算效率高，而且天然符合道路结构。"

**面试必问题 2："绕障怎么做的？"**

> "有三层保障：第一层是成本函数里的安全项，候选路径离障碍物越近成本越高；第二层是 SafetyInspector 硬检查，直接剔除不安全路径；第三层是支持动态采样策略，在障碍物密集区域自动增加采样密度。"

**面试必问题 3："为什么用 Frenet 不用直接在笛卡尔坐标采样？"**

> "Frenet 坐标系把道路约束变成了简单的横向偏移约束，采样空间从 2D 降为 1D。而且 s-d 坐标天然描述了'沿路走了多远、偏了多远'，比 (x,y) 更直观。这是业界 Apollo、OpenPlanner 等都用 Frenet 的原因。"

### Day 4：轨迹规划 + 重构亮点（3h，面试高光点）

**阅读材料**：
- `trajectory_planner/docs/2-架构说明.md`（全文，这份文档质量最高）
- `trajectory_planner/重构说明260212.md`（**重点！这是面试中最能体现工程能力的素材**）

**必须掌握的 4 种速度算法**（不需要懂细节，但要知道区别）：

| 算法 | 一句话 | 适用场景 |
|------|-------|---------|
| PowerBased | 简单梯形速度曲线，计算最快 | 直线、少弯道 |
| Bidirectional | 前后向约束传播，严格保证可行 | 需要硬约束的场景 |
| SmoothBidirectional | 在双向基础上加平滑，兼顾舒适性 | **默认推荐** |
| TOPP | 时间最优，理论上最快的 | 竞速/效率优先 |

**面试高光素材：重构案例**

> "我主导了 trajectory_planner 的策略模式重构。重构前，SpeedProfilePlannerImpl 是一个 1366 行的巨型类，4 种算法都耦合在一起，加新算法要改主类代码，没法单独测试。重构后，我把 4 种算法抽象为 ISpeedAlgorithm 策略接口，主类缩减到 300 行只做调度，每种算法独立成类，辅助函数提取到公共 helper。代码行数虽然增加了 200 行，但主类职责减少 70%，每个算法可以独立单元测试，新增算法只需要加一个策略类——完全符合开闭原则。"

> **面试官追问**："你怎么验证重构没破坏原有功能？"  
> **回答**："公共接口完全不变（init/initSpline/makePlan），配置文件格式不变，算法逻辑是逐行迁移的。我们做了回归测试——同样的输入，重构前后输出的轨迹完全一致。"

| Stanley | 单舵轮 | Stanley 公式 | 前轮转向的经典方案 |

### Day 7：预测器 + 运动学（2h，扫尾）

**预测器**（`predictor/docs/2-架构说明.md`）：
> "预测器解决的是**延时补偿**问题。控制指令下发到执行器实际响应有延时，如果直接用当前状态做控制会不准。我们用带时间戳的命令历史做回放——record() 持续记录命令，forecast() 时按延时时间采样历史命令做 RK4 积分推进，输出更接近真实执行器状态的预测值。对于阿克曼底盘，速度链和转向链延时不同，MonosteerProphet 支持双链路独立建模。"

**运动学**（`kinematics/docs/2-架构说明.md`）：
> "运动学模块负责质心命令 → 轮速/转向角的变换。支持 6 种底盘类型，通过 IKinematics 策略接口实现，ChassisTransformer 根据 ChassisType 自动选择对应实现。这样换了底盘只改配置，上层代码完全不用动。"

### Day 10-11：架构总结 + 设计模式归纳（4h）

**准备一份"项目整体介绍"（5 分钟版本）**：

```
【背景】这是一个移动机器人的规划控制库，面向仓储/物流/巡检场景。
【架构】采用分层流水线架构：
  1. Path Planner → 基于 Frenet 坐标系采样，生成无碰撞路径
  2. Trajectory Planner → 在路径上加时间信息，生成速度轮廓
  3. Predictor → 命令延时补偿，提高控制精度
  4. Controller → 12 种控制器覆盖主流底盘类型
  5. Kinematics → 底盘运动学变换，解耦控制与执行
【设计模式】贯穿使用策略模式（采样策略、速度算法、控制器）、
  工厂模式（注册机制）、接口-实现分离（PIMPL）
【代码规模】2.4 万行 C++，7 个 ROS package，1 万行文档
【我的贡献】主导了 trajectory_planner 的策略模式重构，从 1366 行
  巨型类拆分为 4 个独立算法 + 1 个轻量调度器，提高了可测试性和可扩展性。
```

### Day 12：常见面试问题准备（2h）

**高频问题 + 回答要点**：

1. **"你在这个项目里最大的技术挑战是什么？"**
   > trajectory_planner 重构。原类 1366 行职责混乱，4 种算法耦合，不能单独测试。我用策略模式拆分为 4 个独立策略类 + 1 个调度器，主类减少 78% 代码。关键难点在于保证向后兼容——接口不变、配置不变、输出一致。

2. **"为什么选择策略模式而不是别的设计模式？"**
   > 因为 4 种速度算法是"做同一件事的不同方式"——输入相同（算法上下文），输出相同（轨迹）。策略模式天然匹配这种场景。而且业务需求是会动态切换算法的（不同场景用不同算法），策略模式支持运行时切换。

3. **"路径规划和轨迹规划的关系是什么？"**
   > 路径规划解决"走哪条路"（空间信息：x, y, yaw），轨迹规划解决"怎么走这条路"（时间信息：每个位置的速度、加速度）。路径规划输出的是几何路径，轨迹规划在此基础上加上时间维度，变成完整的时空轨迹。

4. **"Frenet 相比笛卡尔坐标有什么优势？"**
   > 采样维度从 2D 降到 1D（只需要采样横向偏移 d）。而且参考线约束天然满足，不会生成穿越道路边界的路径。Apollo、OpenPlanner 等主流方案都用 Frenet。

5. **"怎么保证实时性？"**
   > 采样数量可配置（默认 11 条候选路径），成本评估用轻量级加权和，不做复杂优化。实际运行中规划时间在 XX ms 以内（跑一下测试拿到真实数据）。

6. **"如果有新的底盘类型怎么接入？"**
   > 3 步：① 实现 IKinematics 接口（正逆运动学变换）；② 选择或新增控制器（如果运动特性不同）；③ 在 ChassisType 枚举里加一项。上层代码完全不用改。
