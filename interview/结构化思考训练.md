# AI PM interview 结构化思考训练

## 核心原则

结构化思考不是背标准答案，而是形成一个固定习惯：

> 先识别问题类型，再选择回答骨架，最后填充事实和证据。

## 第一步：识别题目动词

听完题目后，先判断面试官要求你完成什么任务，避免直接跳进熟悉的技术方案。

| 题目动词 | 回答重点 |
| --- | --- |
| 判断是否值得做 | 价值、可行性、风险、验证 |
| 设计一个产品 | 用户、场景、方案、指标、迭代 |
| 分析效果不好 | 定位问题、拆分链路、实验验证 |
| 制定优先级 | 目标、收益、成本、依赖、风险 |
| 复盘一个项目 | 背景、目标、行动、结果、反思 |
| 处理意见冲突 | 共同目标、分歧假设、证据、决策机制 |

例如，题目问“如何判断一个 AI 助手是否值得做”，重点是判断依据，而不是直接说明如何建设 RAG。

## 第二步：使用通用骨架

优先使用“目标—判断—行动—验证”组织答案：

1. **目标**：究竟要解决什么问题？
2. **判断**：需要考察哪些关键变量？
3. **行动**：根据判断采取什么方案？
4. **验证**：如何证明方案有效，何时继续、调整或停止？

以“AI 助手是否值得做”为例：

- 目标：解决真实用户问题，而不是为了使用 AI；
- 判断：问题价值、AI 适配度、数据可行性、风险和成本；
- 行动：选择一个范围明确的 MVP；
- 验证：与人工或旧流程 baseline 对比任务成功率和节省时间。

## 第三步：每个结论都解释“为什么”

只列清单不等于结构化思考。每个判断都要形成因果关系。

较弱的表达：

> 我会分析用户、数据、技术和指标。

更完整的表达：

> 我会先验证使用频率和现有处理成本，因为如果问题低频且人工解决成本很低，即使模型效果不错，也不一定具有足够的产品价值。

## 第四步：区分三个层次

AI PM 回答通常包含三个层次：

1. **产品层**：用户为什么需要，创造什么价值？
2. **系统层**：AI、规则、搜索和 Workflow 如何分工？
3. **模型层**：检索、Prompt、模型和参数如何优化？

正常推导顺序是：

```text
先证明产品问题 → 再设计系统方案 → 最后选择模型技术
```

没有验证产品问题就直接讨论知识库、预处理和召回率，说明回答过早进入了系统层或模型层。

## 第五步：先总述，再展开，最后收口

口头回答采用三段式：

1. **先总述**：用一句话给出判断框架；
2. **再展开**：按三个至五个步骤说明判断和行动；
3. **最后收口**：给出最终决策、验证方式或下一步。

示例：

> 我会从用户价值、AI 适配度和落地风险三个方面判断。第一……第二……第三……因此，我不会直接建设完整产品，而会先选择一个高频、价值明确且风险可控的场景做 MVP，再根据验证结果决定是否扩大范围。

## 每日训练步骤

每天练习三道题，每道题执行以下步骤：

1. 用 10 秒识别题目动词和问题类型；
2. 用 20 秒列出三个至五个一级步骤；
3. 用 2 分钟口头回答，每一步都解释“为什么”；
4. 回答后检查是否包含结论、因果、指标、风险和收口；
5. 根据点评重新回答一次，保留修改前后的差异。

当前阶段的训练目标不是堆积知识点，而是看到问题后，能在 30 秒内搭出清晰、可展开的回答骨架。

## 回答前检查表

- 我是否回答了题目的动词？
- 我是否先说明了总体框架？
- 各步骤之间是否存在因果关系？
- 我是否先讲产品问题，再讲系统和模型？
- 我是否说明了指标、风险和验证方法？
- 最后是否给出了明确的决策或下一步？
