## 一、文档概述

### 1.1 这是什么

一套部署在项目本地的 AGV 运行数据采集与分析平台。核心链路三件事：

```
车端采数据 → 云端存数据 → 前端看数据
```

### 1.2 一句话说清

> 把现场散落的 AGV 运行数据统一采上来、存下来、展示出来，让团队不用翻日志就能看到车队运行状态。

### 1.3 与现有系统的关系

| 系统 | 本平台补充什么 |
|------|-------------|
| 调度系统 | 前端以调度系统插件形式嵌入，复用监控入口 |
| 到点自学习六期 | 已有到点误差分析页面，本平台在此基础上升级为多车多维度的平台化展示 |
| JZAgent / 大圣 | 数据采集层协同，JZAgent 负责车端采集，大圣负责数据联动 |

---

## 二、为什么要做

### 2.1 当前问题

| 问题 | 现状 |
|------|------|
| **数据散落** | 车辆运行数据在各自日志里，没有统一汇聚 |
| **查看不便** | 要看一辆车的到点误差趋势，需要手动翻日志、导数据、画图 |
| **没有多车视角** | 无法同时对比多台车在同一个点位的表现 |
| **没有时间视角** | 无法看一台车过去一周的误差变化趋势 |

### 2.2 做完之后

- 打开一个页面，能看到所有车的到点误差数据
- 能按车辆、点位、时间段筛选
- 能看趋势、做对比
- 数据自动采集、自动入库，不需要人工导出日志

## 四、V1 功能范围

V1 目标：**把到点误差数据从车端采上来、存到服务器、在前端展示出来。**

### 4.1 功能清单

| 模块 | 功能 | 优先级 | 说明 |
|------|------|--------|------|
| **数据采集** | 到点误差数据采集脚本 | P0 | 采集多车、多点、多时间的到点误差，输出到公司侧服务器 |
| **数据采集** | 采集维度 | P0 | 到点精度带上点位 ID 和时间戳；跟踪误差带上路径拓扑 ID 和时间戳；自学习数据一并采集 |
| **数据采集** | 数据来源对接 | P0 | 导航 + 伺服 + WebService（点位信息从 WebService 抓取）；JZAgent 采集 + 大圣联动 |
| **云端存储** | 数据入库 | P0 | 多车数据存入现场服务器，不影响现场性能 |
| **云端存储** | 性能验证 | P0 | 服务器性能测试 + 本地性能测试 |
| **数据分析** | 基于规则的数据分析 | P0 | 对采集数据进行初步统计分析——均值、方差、趋势，为后续扩展提供基础 |
| **数据分析** | 结果级分析 | P0 | 对到点误差做初步的分类统计 |
| **前端展示** | 看板嵌入调度前端 | P0 | 以调度系统插件形式部署，不另开端口，设计需结合调度前端迭代版本 |
| **前端展示** | 数据整体导出 | P1 | 支持打包导出，初期先手动拉取 |

### 4.2 V1 不做

- ❌ 不做过程级数据（横向误差、角度误差、打滑、定位跳变）—— V2 再上
- ❌ 不做自动诊断/根因分析/责任归因
- ❌ 不做健康度评分/维保建议
- ❌ 不做自动告警推送
- ❌ 不自动开启数据采集——先手动控制单台车开关

## 五、数据采集

### 5.1 采集范围（V1）

**已有数据源**（到点自学习六期已具备）：

| 数据项 | 说明 |
|--------|------|
| 到点控制误差 | control_error_x/y/yaw |
| 到点闭环误差 | tag_error_x/y/yaw |
| 定位误差 | loc_error = tag_error - control_error |

**V1 新增采集**（仅到点结果级，非过程级）：

无。V1 先用已有数据跑通全链路。过程级数据（横向误差、角度误差、打滑、定位跳变等）在 V2 引入。

### 5.2 采集维度要求

采集的每一条数据必须带齐以下维度，否则后续分析无法做：

```
车辆 ID      — 区分不同车
点位 ID      — 区分不同站点
时间戳       — 区分不同时刻
路径拓扑 ID   — 跟踪误差需要绑定路径段
任务 ID      — 可选，用于关联业务上下文
地图 ID      — 地图版本变更时需要区分
```

### 5.3 采集策略

- **手动开关**：V1 逐车手动开启/关闭采集，不做自动触发
- **定时采集**：车端节点按固定频率采集，有任务时采、无任务时停
- **性能要求**：采集过程不应对车辆正常运行产生影响
- **测试要求**：以最少 3×24h 连续采集为基准，测试占用空间和性能

## 六、云端存储

### 6.1 存储位置

- 部署在项目本地服务器
- 数据不出内网

### 6.2 数据库表设计（arrival_record）

```
robot_id          | 车辆 ID
map_id            | 地图 ID
task_id           | 任务 ID（可选）
path_id           | 路径 ID
point_id          | 点位 ID
timestamp         | 到点时间
approach_direction| 接近方向

-- 误差字段
control_error_x   | 控制误差 X
control_error_y   | 控制误差 Y
control_error_yaw | 控制误差角度
tag_error_x       | 闭环误差 X
tag_error_y       | 闭环误差 Y
tag_error_yaw     | 闭环误差角度
loc_error_x       | 定位误差 X（tag - control）
loc_error_y       | 定位误差 Y
loc_error_yaw     | 定位误差角度

-- 版本字段（用于后续版本回归分析）
planner_version   | 规划器版本
controller_version| 控制器版本
loc_version       | 定位版本
```

### 6.3 存储性能要求

| 指标 | 要求 |
|------|------|
| 入库延迟 | 不影响车辆运行 |
| 服务器负载 | 通过性能测试验收 |
| 数据保留 | 不丢失、不截断 |

## 七、数据分析

### 7.1 V1 分析内容

V1 不做复杂诊断。数据分析止于**基于规则的统计和展示**：

| 分析项 | 说明 | 方法 |
|--------|------|------|
| 按车辆统计 | 每台车的到点误差均值、方差、最大值 | 规则聚合 |
| 按点位统计 | 每个点位的到点误差均值、方差、最大值 | 规则聚合 |
| 按时间趋势 | 某车/某点位的误差随时间变化趋势 | 折线图 |
| 多车对比 | 多台车在同一个点位的误差对比 | 柱状图/表格 |

### 7.2 V1 不做

- ❌ 不做根因分析（不判断是车体问题还是环境问题）
- ❌ 不做责任归因
- ❌ 不做健康评分
- ❌ 不做 ML/统计学习模型

V1 的核心任务是**把数据跑通**，让人能看到数据。分析先做最基础的聚合统计，保证数据是对的、能看的。

## 八、前端展示

### 8.1 部署方式

- 以调度系统**插件**形式嵌入
- 复用调度前端机器人监控入口
- 不另开端口
- 前端设计需结合调度前端迭代版本

### 8.2 V1 页面

| 页面 | 内容 |
|------|------|
| 多车到点误差总览 | 所有车辆/点位的误差概览表 |
| 单车趋势 | 选定一台车，看它在不同点位的误差趋势折线图 |
| 点位对比 | 选定一个点位，看不同车在此点位的误差对比 |
| 数据导出 | 支持按筛选条件打包导出（初期手动拉取） |

### 8.3 交互要求

- 支持按车辆筛选（单选/多选）
- 支持按点位/区域筛选
- 支持按时间段筛选
- 数据可视化：折线图、柱状图、表格

## 十二、风险

| 风险 | 应对 |
|------|------|
| 现场服务器性能不足 | P0 必须做性能测试 |
| 不同车型/版本数据格式不一致 | 车端采集层统一标准化输出 |
| JZAgent + 大圣联调复杂 | 先单车单数据类型跑通，再扩展 |
| 前端嵌入调度系统的兼容性 | 与调度前端团队提前对齐迭代版本 |
