## 一、系统全景速览

```
nav-manager (~38K LOC)
├── Manager (任务管理层, ~15K)
│   ├── Router          → 路径搜索、拼接、裁断
│   ├── Map             → 地图管理、轨迹处理
│   ├── Localization    → 定位管理（激光/码）
│   ├── Code Inserting  → 精度管理、异常检查、转盘控制、热启动
│   ├── Data Collection → 自学习数据采集与补偿
│   ├── Dispatch        → 调度任务协同
│   ├── Plugin          → Nav/Servo 插件
│   └── Visualmark      → 二维码检测
├── Nav Core (~3K)      → EventBus / ConfigMaster
├── Nav Base (~8K)      → 任务执行编排 / 状态同步 / 上道修正
├── Nav Controller (~10K)→ 运动控制 / 底盘驱动 / 安全检测 / 运动状态机
└── Nav Planner (~5K)   → 轨迹生成 / BCC 平滑 / 脱轨路径
```

### 🔶 模块 A：路径管理与多源任务裁断系统（hehongjie 主导）

**代码位置**：`manager/src/router/` + `manager/src/code_inserting/pruner.cpp`

**核心文件**：
| 文件 | 行数 | 职责 |
|------|------|------|
| `route_processor.cpp` | 803 | 路径处理、起始索引计算、属性合并 |
| `pruner.cpp` | 621 | 硬裁断逻辑、前后端索引管理 |
| `jz_router_generator.cpp` | 440 | 路由生成、路径拼接、终点设置 |
| `low_code_process.cpp` | 227 | 低代码路径计算与调试 |

**解决的问题**：
1. **多源任务路径拼接**：自搜路、新调度、老调度、第三方调度等多种来源需要统一拼接和裁断。
2. **硬裁断（Hard Pruning）**：在不同任务边界对路径"硬裁断"，确保相邻任务路径不重不漏、属性正确传递。
3. **低代码路径计算**：在简化配置场景下自动计算路径距离和索引。
4. **路径点过滤与去重**：按地图方向过滤连续重复路径点，避免冗余导航指令。
5. **斜移（Slant）属性支持**：横向移动/斜移路径点的属性传递和合并。

**他洪杰的具体贡献**：
- 设计并实现 `pruner` 硬裁断模块（6月-7月大量迭代）
- 优化 `route_processor` 起点索引计算、路径点属性合并
- 修复 `jz_router_generator` 多处索引越界和路径拼接问题
- 实现路径状态过滤 + 地图方向去重
- 移除废弃 `War` 类，简化路径管理架构
- 关键提交：`12eaebe9`, `ec94fe9c`, `6624e3b1`, `5ef53379`, `0adb1943`

**含金量**：⭐⭐⭐⭐⭐ 很高——路径管理是导航系统的骨架，直接影响所有任务类型正确性。

**简历包装建议**（你可说的）：
> "在 nav-manager 导航系统中，我参与了路径管理层的联调与优化，团队实现了多源任务（自搜路/新调度/老调度）的统一路径拼接与硬裁断机制，并解决了路径点去重和索引越界等稳定性问题。我主要负责了到点补偿链路与路径管理的接口对接。"

### 🔶 模块 C：定位源管理与二维码/激光切换（hehongjie + zhr + wuhaoxian）

**代码位置**：`manager/src/code_inserting/hotstart_manager.cpp` (865 行) + `manager/src/visualmark_detect/`

**解决的体系级问题**：

3. **HotStartManager 增强**：新增结构体和方法管理多源切换（他洪杰）。
4. **TF 发布支持**：TransformBroadcaster for NavPlugin（wuhaoxian）。

**含金量**：⭐⭐⭐⭐ 高——定位源切换是导航连续性的核心保障。

**简历包装建议**（你可说的）：

### 🔶 模块 E：运动控制器与多车型适配（wr 主导）

**代码位置**：`navigation/nav_controller/` + `navigation/nav_local_planner/`

**解决的问题**：
1. **贝塞尔曲线轨迹**：用作导航轨迹生成，处理直线/弯道平滑切换。
2. **舵轮控制优化**：舵角抖动、超限、横向误差不收敛、非对称限位适配、舵角变化率限制。
3. **LQR 控制器**：差分车二维码导航使用 LQR 替代 bang-bang。
4. **速度重规划优化**：过弯、被限速、离终点近、退出 IDLE 时均不触发重规划。
5. **横移/Slant 模式**：专用控制器适配、斜移独立规划、横移修正、边走边转。
6. **特种车型适配**：
   - 宇树狗：旋转步态适配、反馈不参与控制、不从 near 切换到 turnrotate
   - 叉车：控制器参数适配
   - 双舵轮：横向控制增益、bsc 控制器
   - 智身科技机器狗适配

**含金量**：⭐⭐⭐⭐ 高——控制器是导航"最后一公里"，车型适配直接影响客户交付。

**简历包装建议**（你可说的）：
> "导航控制层覆盖了差速、舵轮、叉车、宇树狗等多种车型。我在联调中参与了叉车/差分车的到点精度验证和控制参数适配，配合控制器团队解决了转弯时速度重规划过度触发等问题。"

## 四、终极建议：三种"退一步包装"策略

### 策略 1：系统级参与 + 模块级深度

> "在 38K 行的机器人导航系统中，我深度参与了 Manager 层的到点精度闭环（自学习采集→补偿注入→热更新→精度校验），并协同路径管理、定位切换和调度协同等模块完成联调与边界修复。近两年提交 330+ 条，覆盖精度补偿、定位切换、热更新稳定性和现场诊断四大方向。"

✅ 好处：说清楚你做了什么（精度闭环），暗示你了解全局（路径/定位/调度），显得有系统视野。

### 策略 2：以问题域归类，不署名模块

> "我参与解决的导航系统核心问题包括：
> - **到点精度**：不同楼层/载荷下补偿值条件化匹配与热更新生效
> - **定位切换**：二维码/激光协同切换的时序控制与单边/末边保护
> - **并发稳定性**：地图热更新竞态修复与嵌套锁死锁排查
> - **现场可观测**：到点后精度校验规则与关键路径诊断日志"

✅ 好处：以"问题→解法"叙事，不涉及模块归属争议。

### 策略 3：突出"稳定性专家"标签

> "我在项目中主要承担导航系统稳定性和现场可观测性的角色：
> - 修复了多起因并发、边界条件和时序错误导致的现场崩溃/精度异常问题
> - 建立了到点精度的数据闭环（采集→补偿→校验），支撑多楼层/多负载场景
> - 补齐了关键路径上的诊断日志，支撑远程问题定位，减少现场排查时间"

✅ 好处：不抢核心算法光环，但同样高价值。
