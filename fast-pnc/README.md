## Day1：整体框架 + 数据链路

### 🎯 一句话总结
**PNC = 把参考路径变成车辆能执行的底盘命令的全链路算法。**

### 🔗 核心数据流（面试必画）

```
参考路径 (Reference Path)
    ↓
路径规划 (path_planner)   → 生成几何路径（去哪条路）
    ↓
速度规划 (trajectory_planner) → 生成带时间/速度的轨迹（以什么速度走）
    ↓
控制器 (controller)       → 跟踪轨迹，输出质心命令 (vx, vy, w)
    ↓                         ↑ 预测器(predictor) 补偿执行延迟
运动学 (kinematics)       → 质心命令 → 执行器命令（轮速/舵角）
    ↓
底盘执行
```

### 📦 六模块职责速记

| 模块 | 一句话职责 | 核心输入 | 核心输出 |
|------|-----------|---------|---------|
| `core` | 数据协议，所有模块的共同语言 | - | `VehicleState`, `CentroidTrajectory`, `CentroidCommand` |
| `path_planner` | Frenet 坐标系采样生成几何路径 | 参考路径、车辆状态、障碍物 | `BasicPath`（几何路径） |
| `trajectory_planner` | 给路径配上速度和时间的曲线 | 几何路径、速度约束 | `CentroidTrajectory`（带时间的轨迹） |
| `controller` | 轨迹跟踪，消除位置/姿态误差 | 轨迹、车辆状态 | `CentroidCommand`（vx/vy/w） |
| `predictor` | 用历史命令预测"命令生效时"的车辆状态 | 历史命令、当前状态 | 预测状态 |
| `kinematics` | 质心层 ↔ 执行器层坐标变换 | 质心命令 / 执行器状态 | 执行器命令 / 质心状态 |

### 🏗️ 架构设计理念（亮点说辞）

- **稳定数据协议**：各模块只交换统一状态/轨迹/命令，不关心内部实现
- **工厂模式 + 注册表模式**：控制器通过 `controller_id` 字符串注册/切换，新增控制器不改主流程
- **策略模式**：路径规划 `SMOOTH/AVOID` 两套策略，同一入口切换
- **组合优先**：外部系统组合各模块能力，算法库不固化业务流程
- **依赖倒置**：高层算法依赖抽象接口（如 `SafetyInspector`），外部注入实现

> **面试金句**："PNC 的设计核心是协议稳定、算法可插拔、业务可组合。core 提供通用语言，各模块只负责单一职责，上层系统按场景组合。"

## Day2：路径规划 + 速度规划

### 🛣️ 路径规划 (path_planner)

#### 什么是 Frenet 坐标系？
- 不再用全局 `(x, y)` 描述路径，而是用 `(s, l)`：
  - **s**：沿参考路径的弧长（"走了多远"）
  - **l**：相对参考路径的横向偏移（"偏左还是偏右"）
- **好处**：纵向推进和横向绕障可以分开建模

#### 核心流程
```
车辆状态投影到参考路径 → 得到 Frenet 起点 (s0, l0, dl0, ddl0)
    ↓
纵向采样多个 s_end，横向采样多个 l_end
    ↓
每组 (s_end, l_end) 用 5次多项式 生成候选路径
    ↓
转回全局坐标 → 曲率检查 → 碰撞检测
    ↓
7维成本函数评估（跟踪/长度/连贯/倾向/jerk/曲率/碰撞）
    ↓
选成本最小的有效路径
```

#### 5次多项式
```
l(s) = a₀ + a₁s + a₂s² + a₃s³ + a₄s⁴ + a₅s⁵
```
6个系数，用 6 个边界条件求解（起点和终点的 l, dl, ddl），保证位置/速度/加速度连续。

#### 到达模式
剩余距离 < 阈值时，不再大范围绕障采样，而是平滑回归参考路径终点。

#### 面试可能问
> **Q: Frenet 采样和直接 XY 采样有什么区别？**
> A: Frenet 把二维搜索变成"沿路走多远 × 偏多少"的一维+一维问题；天然跟随参考路径走向；成本函数更容易表达跟踪偏差和横向偏移。

> **Q: 为什么不直接发给控制器，还要速度规划？**
> A: 几何路径只有空间信息，控制器不知道"每个点多快通过"、"什么时候到终点"、"转弯要不要减速"。速度规划解决这些问题。

---

### ⚡ 速度规划 (trajectory_planner)

#### 核心问题
给定路径，在速度上限、曲率限速、加减速约束、jerk 约束下，生成平滑的速度曲线 `v(s)`。

#### 三种算法对比

| 算法 | 核心思路 | 优缺点 |
|------|---------|--------|
| **Bidirectional** | 前向加速扫描 + 后向减速扫描 → 取 min | 最快，但加速度可能不平滑 |
| **TOPP** | 时间最优参数化，贴近速度上界 | 更高效，平滑性依赖后处理 |
| **SmoothBidirectional** ⭐ | 双向+加速度平滑+jerk投影+末端Hermite平滑 | 默认算法，最平滑，最可跟踪 |

#### 双向扫描原理
```
前向：v[i] ≤ sqrt(v[i-1]² + 2·a_max·ds)    // 不能超过加速能力
后向：v[i] ≤ sqrt(v[i+1]² + 2·d_max·ds)    // 剩余距离内能减速到终点
最终：v[i] = min(v_max[i], v_forward[i], v_backward[i])
```

#### 速度上界来源
```
v_max(s) = min(全局max_v, 分段限速, 曲率限速(max_w/|κ|), 底盘几何约束)
```

#### SmoothBidirectional 完整流程
1. 等弧长采样 ds=0.02m
2. 计算每点曲率，构造 v_max
3. 保守滑动平均平滑 v_max（只降不升）
4. 迭代：平滑加速度 → 积分得速度 → 投影回可行域 → 欠松弛更新
5. 末端 Hermite 平滑停车
6. 时间化（dt = ds/v）

#### 面试可能问
> **Q: 为什么需要速度规划？直接匀速不行吗？**
> A: 不安全也不高效。转弯曲率大要降速，终点要停车，加减速有物理约束。没有速度规划容易翻车或停不准。

## Day3：控制器（面试重点⭐）

### 控制器总览

| 控制器 | 适用底盘 | 一句话原理 |
|--------|----------|-----------|
| **PathFollow** | 差速 | 纵向二阶误差 + 横向角速度反馈 + 曲率前馈 |
| **Stanley** | 单舵/阿克曼 | 航向误差 + atan(k·横向误差/v) |
| **LQR** | 差速 | 三状态误差模型 + DARE解反馈增益 |
| **OmniFollow** | 全向 | 速度模长+方向分开控制，横纵向独立 |
| **Headlock** | 全向 | 沿路径平移但保持固定车头朝向 |
| **BangBang** | 低速纠偏 | 误差>阈值→满载输出，<阈值→0 |
| **Bistanley/BisteerDiffer** | 双舵 | Stanley/差动思想在双舵结构扩展 |

---

### ⭐ Stanley 控制器（高频面试算法）

**公式**：
```
δ = heading_error + atan(k × lateral_error / (v + ε))
```
- `k`：横向误差增益
- `v`：当前速度
- `eps`：防除零
- **速度越低，横向误差项影响越大；速度越高，控制越平滑**

**工程实现要关注**：
- 低速时横向误差项容易过大，需要限幅
- 路径曲率突变处航向误差会放大
- 倒车/接近终点需要特殊处理

---

### ⭐ LQR 控制器（高频面试算法）

**核心思想**：把轨迹跟踪写成线性状态空间，用二次型代价显式权衡误差和控制量大小。

**状态模型（三状态）**：
```
x = [ey, eψ, w_fb]ᵀ
ey   = 横向误差
eψ   = 航向误差
w_fb = 上一周期反馈角速度
```

**离散状态方程**：
```
A = [1,  v·dt, 0
     0,  1,    dt
     0,  0,    1  ]

B = [0, 0, dt]ᵀ
```

**代价函数**：
```
J = Σ(xᵀQx + uᵀRu)
Q = diag(Q_ey, Q_eψ, Q_w)
R = R_ẇ
```

**求解**：DARE（离散代数 Riccati 方程）迭代求反馈增益 K
```
u = -K·x          // 最优反馈
w_cmd = w_ff + w_fb + ∫(Ki_ey·ey·dt)  // 前馈+反馈+积分项（带anti-windup）
```

**Stanley vs LQR**：

| 维度 | Stanley | LQR |
|------|---------|-----|
| 优化方式 | 几何/启发式 | 最优控制（最小化代价） |
| 权重调参 | 少数参数 | Q/R 权重矩阵，更灵活 |
| 平滑性 | 依赖参数 | 天然平滑 |
| 计算开销 | 低 | 中等（DARE迭代） |
| 适用性 | 非全向底盘 | 任意底盘，需建状态模型 |

---

### NORMAL vs ASYNCHRO_STEER 控制模板

- **NORMAL**：用预测器统一预测状态，控制器基于预测状态一次跟踪
- **ASYNCHRO_STEER**：轮速和转向延迟不同，分开预测 → 分开控制 → 合成质心命令

> **面试说辞**："单舵车的轮速响应和舵角响应延迟不同，如果用一个预测点同时控制，会出现速度和转角不匹配，导致跟踪抖动。"

## Day4：预测器 + 运动学

### 🔮 预测器 (predictor)

**核心问题**：控制命令从计算到执行有延迟（几十~几百毫秒），如果始终用"当前定位"算误差，车辆会在曲线处滞后。

**解决方案**：用历史命令按真实时序回放，预测"命令生效时车辆在哪"，控制器再用这个预测状态做跟踪。

**两种实现**：

| 类型 | 适用场景 | 原理 |
|------|---------|------|
| `CentroidProphet` | 差速/全向（单一延迟链路） | 回放历史质心命令 vx/vy/w，RK4积分推演 |
| `MonosteerProphet` | 单舵（两条延迟链路） | 轮速链 + 舵角链分开回放，四种越界情况处理 |

**四种越界处理**（Monosteer 独有）：
1. 两链都可观测 → 正常组合
2. 转向链越界 → 速度链命令 + 参考轨迹舵角
3. 速度链越界 → 转向链命令 + 参考轨迹轮速
4. 两链都越界 → 用最后可得命令保持

**积分方法**：RK4（四阶 Runge-Kutta），比欧拉积分更准，尤其在角速度变化时。

---

### 🔧 运动学 (kinematics)

**职责**：质心层（vx, vy, w）↔ 执行器层（轮速、舵角）

**差速底盘**：
```
正运动学：vx = (v_l + v_r)/2,  w = (v_r - v_l)/track_width
逆运动学：v_l = vx - w·track_width/2,  v_r = vx + w·track_width/2
```

**麦克纳姆底盘**：
```
正运动学：vx = (v0+v1+v2+v3)/4
         vy = (v0-v1+v2-v3)/4
         w  = (v0-v1-v2+v3)/(4·rot_len)
```
支持全向移动，`vy` 不为 0。

**舵轮底盘**：需要处理舵角多解（等效角选择）、舵角连续性、舵轮中心与质心不重合等工程问题。

## Day5：架构设计 + 面试常见问答

### 🏗️ 设计模式速查

| 模式 | 体现 | 面试说辞 |
|------|------|---------|
| 工厂模式 | `create()` 创建各模块实例 | "调用方依赖抽象创建，实现隐藏在模块内部" |
| 注册表模式 | `registerController("id")` 注册控制器 | "新增控制算法只需实现接口+注册，不改主流程" |
| 策略模式 | `SMOOTH/AVOID` 采样策略切换 | "平滑和绕障共享入口，策略差异内聚在模块内部" |

| 依赖倒置 | 依赖抽象 `SafetyInspector`、`ChassisTransformer` | "高层算法不绑定具体底盘或地图实现" |

### 🎤 面试模拟 10 问

1. **Q: 介绍一下 PNC 的整体架构？**
   A: 画数据流图，讲六模块职责、输入输出。

2. **Q: 为什么要用 Frenet 坐标系做路径规划？**
   A: 纵向推进和横向绕障解耦；天然跟随参考路径；成本函数更直观。

3. **Q: 路径规划怎么生成候选路径？**
   A: 采样 `(s_end, l_end)`，用5次多项式拟合6个边界条件，转回全局坐标做碰撞检测和成本评估。

4. **Q: 速度规划的 SmoothBidirectional 算法怎么做的？**
   A: 构造 v_max → 双向扫描 → 加速度平滑 → jerk投影 → 欠松弛迭代 → 末端Hermite平滑。

5. **Q: Stanley 控制器的原理？**
   A: `δ = eψ + atan(k·ey/v)`，航向误差+横向误差(速度越低权重越大)。

6. **Q: LQR 控制器和 Stanley 的区别？**
   A: LQR 是基于模型的最优控制，通过 Q/R 权重矩阵权衡多目标；Stanley 是几何/启发式。LQR 更平滑但需要建状态模型。

7. **Q: 预测器是干什么的？**
   A: 补偿控制命令执行延迟。用历史命令回放，RK4积分，估计"命令生效时"车辆状态，控制器再基于这个预测状态做跟踪。

8. **Q: NORMAL 和 ASYNCHRO_STEER 控制模板有什么区别？**
   A: NORMAL 单一预测状态同时控制速度和转向；ASYNCHRO_STEER 轮速和转向分开预测和控制再合成，解决单舵车两条链路延迟不一致问题。

9. **Q: 差速底盘的逆运动学公式？**
   A: `v_l = vx - w·d/2`, `v_r = vx + w·d/2`。

10. **Q: 你们的 PNC 有什么架构亮点？**
    A: 稳定数据协议 + 工厂/注册表/策略模式 + 组合优先；模块职责单一、算法可插拔、业务可组合；2026年核心工程化了预测补偿、统一了速度规划链路。
